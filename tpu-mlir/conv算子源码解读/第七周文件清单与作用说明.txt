================================================================================
  一、MLIR 理论基础（先建立概念）
================================================================================

学习资源：MLIR Toy Tutorial Ch.3–6
网址：https://mlir.llvm.org/docs/Tutorials/Toy/

要掌握的概念：
  - Operation / Value / Type / Attr：IR 的基本元素
  - Region / Block：IR 的结构容器
  - TableGen (.td)：用声明式语言定义算子，自动生成 C++ 代码
  - Pass / PassManager：对 IR 做变换的框架
  - Pattern Rewrite：匹配 IR 模式 → 替换为新模式

对应的 tpu-mlir 实例：
  - TableGen 示例 → include/tpu_mlir/Dialect/Top/IR/TopOps.td（见下方）
  - Pattern Rewrite 示例 → lib/Dialect/Top/Canonicalize/Conv.cpp（见下方）


================================================================================
  二、前端路径 — ONNX 模型怎么变成 Top IR
================================================================================

[1] python/tools/model_transform.py
    作用：命令行入口 + 流程编排
    职责：
      - 解析命令行参数（模型路径、input shape、精度等）
      - 创建 OnnxTransformer（或 TfliteTransformer 等）
      - 调用 converter.generate_mlir() → 生成 origin.mlir
      - 调用 mlir_opt_for_top() → 跑 Canonicalize Pass → 生成最终的 top mlir
    一句话：先调 Converter 生成 mlir，再调 tpuc-opt 跑图优化，把两步串起来。

[2] python/transform/OnnxConverter.py
    作用：ONNX 算子 → Top Dialect 算子的翻译官
    核心机制：
      - onnxop_factory 字典：{"Conv": convert_conv_op, "Relu": convert_relu_op, ...}
        每个 ONNX 算子名对应一个 Python 函数
      - 遍历 ONNX 模型的所有节点，逐个调对应函数翻译成 top.XxxOp
      - convert_conv_op() 函数（第 981 行）：
          ① 从 ONNX 节点读 kernel_shape / strides / pads / group / dilations
          ② self.getOp() 拿上游的输入 Value 和 filter Value
          ③ self.getWeightOp() 创建 bias 的 Weight Op
          ④ top.ConvOp(operands, kernel_shape=..., strides=..., ...) → 创建 Top IR Op
          ⑤ self.addOperand(name, op) → 注册到符号表
    一句话：把 ONNX 图的每个节点按字典逐条翻译成 Top Dialect 的 Op。

[3] python/transform/BaseConverter.py
    作用：全局符号表（"名字 → 东西"的字典）
    维护的映射：
      - self.operands：名字 → MLIR Value（每个算子的输出）
      - self.tensors：名字 → numpy 数组（权重数据）
      - self.shapes：名字 → shape 列表
      - self.input_names / output_names：模型的输入/输出名列表
    关键方法：
      - addOperand(name, op)：注册"这个算子的输出 Value 叫什么"
      - getOperand(name)：下游算子通过名字拿上游的输出 Value
      - addWeight(name, data)：存权重 numpy 数组，强制转 f32
      - getWeightOp(name)：调用 MLIRImporter 创建 top.Weight Op
      - WeightToNpz()：把所有 tensor 写入 .npz 文件
    一句话：ONNX 靠字符串名字连算子，BaseConverter 就是名字→Value/Weight 的映射表。

[4] python/transform/MLIRImporter.py
    作用：MLIR IR 的"施工队"，用 Python 绑定在内存里建 IR
    核心能力：
      - __init__：创建 MLIR Context + Location，声明 module + func
      - create_input_op()：创建 top.Input Op
      - create_weight_op()：创建 top.Weight Op
      - create_return_op()：创建 func.return
      - print_module()：把内存里的 IR 序列化成 .mlir 文本文件
      使用的 Python 库：from mlir.ir import *（MLIR 官方 Python 绑定）
    一句话：OnnxConverter 说"我要建一个 Conv"，MLIRImporter 就在内存里实实在在地建。


================================================================================
  三、算子编译管线 — Conv 从 Top IR 到 bmodel
================================================================================

[5] include/tpu_mlir/Dialect/Top/IR/TopOps.td
    作用：TableGen 声明式定义 Top Dialect 的所有算子
    Conv 相关（第 1411 行 def Top_ConvOp）：
      - 声明 Conv 的输入（input, filter, bias）
      - 声明 Conv 的输出（output）
      - 声明 Conv 的属性（kernel_shape, strides, pads, group, dilations,
        do_relu, relu_limit, auto_pad, weight_is_coeff, dynweight_reorderd...）
      - 声明 Conv 实现了哪些 Interface（SupportFuseRelu, InferenceInterface）
    一句话：用 .td 声明式语言定义 Conv 的输入/输出/属性，编译时自动生成 C++ 类。

[6] lib/Dialect/Top/Interfaces/Conv.cpp
    作用：Conv 算子的通用逻辑实现
    包含：
      - shape 推断：根据输入 shape + kernel_shape + strides + pads 算出输出 shape
      - 量化参数计算：怎么得到 scale/zero_point
      - backward_weight：反向传播时 weight 梯度的计算
    一句话：实现 Conv 的 shape 推断和量化参数计算等通用逻辑。

[7] lib/Dialect/Top/Canonicalize/Conv.cpp
    作用：Conv 相关的图优化（Pattern Rewrite）
    包含的 Pattern：
      - Conv1dTo2d：1D 卷积适配为 2D 卷积（kernel_shape/strides/pads 补 1）
      - Conv+ReLU 融合：do_relu = false → true，删除独立 ReLU Op
      - Conv+BN 融合：把 BatchNorm 的乘加合并到 Conv 的 weight/bias 里
      - Conv+Add 融合：残差连接的 Add 合并到 Conv
    核心骨架：
      struct XxxPattern : public OpRewriterPatternEx<ConvOp> {
        LogicalResult matchAndRewriteImpl(ConvOp op, PatternRewriter &rewriter) {
          // 匹配条件 → 创建新 Op → 替换旧 Op
        }
      };
    一句话：用 Pattern Rewrite 做算子融合和适配，减少算子数量、优化计算图。

[8] lib/Dialect/Top/Transforms/ProcessorOptimize/OptimizeBM1684X.cpp
    作用：针对 BM1684X 芯片的特殊图优化
    内容：
      - 对 BM1684X 不友好的算子组合做拆解或替换
      - 比如将 Unsqueeze→Expand→Reshape→Transpose→MatMul 组合优化掉
      - 特定模型的 pattern 匹配和替换
    一句话：在 Top 层对 BM1684X 芯片做针对性的图结构调整。

[9] lib/Conversion/TopToTpu/BM1684X/Conv.cpp
    作用：Top Dialect → Tpu Dialect 的 Lowering（最关键的转换！）
    包含三条路径：
      - LoweringF16（第 641 行）：
          ① 遍历 input 和 filter → 如果是 WeightOp，调 weightOp.clone_f16(op) 转 f16
          ② bias 保持 f32
          ③ 拷贝所有旧属性 + 加 with_bias
          ④ 输出类型换为 getQuantF16Type()
          ⑤ CreateConvOp() → 创建 tpu.Conv2D
          ⑥ rewriter.replaceOp() → 替换旧 top.Conv
      - LoweringINT8（第 56 行）：
          ① 读 calibration table → getScaleAndZeroPoint() 拿 in/out scale+zp
          ② findMinMax() 统计 filter 的 min/max
          ③ filter f32→int8（fsign<0 则对称量化到[-127,127]，否则非对称到[0,255]）
          ④ bias f32→int32（bias_scale = input_scale × weight_scale）
          ⑤ 创建量化后的 tpu.Conv2D
      - LoweringBF16（第 608 行）：与 F16 类似，clone_bf16()
    一句话：top.Conv 变成 tpu.Conv2D，F16 只需转类型，INT8 需要校准表+量化 weight/bias。

[10] lib/Dialect/Tpu/Transforms/LayerGroup/
     作用：层组优化 — 对网络切分，让尽量多的 OP 在 local memory 上连续计算
     关键文件：
       - GroupMethod.cpp：分组策略，决定哪些算子分到一组
       - LmemAllocator.cpp：local memory 分配，张量怎么塞进片上内存
       - TimeStepMethod.cpp / BasicTimeStep.cpp：时间步流水，组内算子怎么流水执行
       - CycleCalculator.cpp：cost model，预估每组耗时
       - GroupOps.cpp：把选定的 Op 包进 tpu.Group
       - LgPass.cpp：LayerGroup 的 Pass 入口
     效果：平铺 Op 变成 Group 嵌套结构（tpu.Load → Conv → Pool → Store → Yield）
     一句话：把网络切成一组一组，每组在片上 local memory 内完成 Load→Compute→Store 流水线。

[11] lib/Dialect/Tpu/Transforms/Codegen/
     作用：代码生成 — final.mlir → cmdbuf → bmodel 二进制
     关键文件：
       - BM168xCodegen.cpp：BM1684X 的 codegen 主逻辑，遍历所有 Op 调 codegen 接口
       - TensorLocation.cpp：管理 tensor 的物理存储位置
       - BM168xEvaluator.cpp：硬件性能评估
     流程：
       ① 遍历 final.mlir 中所有 Op
       ② 每个 Op 调用自己的 codegen 接口 → 生成 cmdbuf（指令缓冲区）
       ③ Builder 模块用 flatbuffers 格式序列化 cmdbuf → 输出 .bmodel 文件
     一句话：把带地址和 Group 的 TPU IR 翻译成芯片能执行的二进制指令流。

================================================================================
  核心学习建议（来自第七周学习指南）
================================================================================

1. 以 Conv 为线索串所有文件 — 每个文件都围绕同一个算子，形成一条线
2. 每读完一个文件，用一句话记笔记（不要抄代码，写"这个文件做了什么"）
3. 画图：一条时间线，Conv 在每个阶段变成了什么样子
4. 碰到不懂的类/函数，用 grep 搜定义，别猜

带着这些问题读：
  - INT8 量化路径和 F16 路径在 lowering 时有什么不同？
  - LayerGroup 凭什么决定哪些算子分到一组？
  - 如果 local memory 放不下一个 tensor，代码里怎么处理？
  - 从 IR 到 bmodel 二进制，中间少了什么信息？加了什么信息？
