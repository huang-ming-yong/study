================================================================================
            LayerGroup Pass —— 反向推断每层 Tensor 大小流程说明
================================================================================

一、背景：为什么要反向推断？
--------------------------------------------------------------------------------

一个 Group 包含多个连续的 OP（算子）。LayerGroup 的目标是让所有中间数据
都留在片内内存（LMEM）里，避免反复与片外内存（DDR）交换数据。

但 LMEM 容量有限（通常只有 16MB），一整层的输入输出可能很大，无法一次性
全部放入。因此需要把数据切成小块（tile），分批加载、分批计算、分批存出。

核心问题是：如果已经确定了最后一层输出的切分方式，那前面每一层的输入
应该切成什么样？这就需要从输出端向输入端进行"反向推断"。

反向推断的输入：
  - shape_secs：切分方案，例如 {nsecs=2, csecs=1, hsecs=4, dsecs=1, wsecs=1}
    表示 N 维度切 2 份，H 维度切 4 份，其他维度不切
  - lg_info：当前分组信息（包含哪些 OP、哪些是输入、哪些是输出）

反向推断的输出：
  - tensor_infos：Group 中每条边上 tensor 的切分信息（每份 tile 的起始偏移和长度）


二、整体流程概览
--------------------------------------------------------------------------------

1. 从 Group 的最终输出 tensor 出发，按 shape_secs 将其切分成多个 tile
2. 将输出 tensor 加入 BFS 队列
3. 从队列中取出一个 tensor，找到生产它的 OP
4. 对该 OP 的每个输入 operand，根据输出的切分反推输入的切分
5. 将新推断出的 tensor 信息存入 tensor_infos
6. 判断是否需要将输入 tensor 继续加入队列向上传播
7. 如果遇到多分支（同一 tensor 被多个下游 OP 引用），需要做一致性检查
8. 循环直到队列为空


三、详细步骤
--------------------------------------------------------------------------------

3.1 第一步：初始化 —— 切割 Group 的输出

拿到 shape_secs 后，首先处理 Group 的所有输出 tensor：

- 获取输出 tensor 的完整尺寸（N, C, D, H, W）
- 按 shape_secs 计算每个维度切几份、每份多大
- 例如：H 维总长 100，hsecs=4，则切成 [0,25)、[25,50)、[50,75)、[75,100)
- 将切分信息存入 tensor_infos[输出tensor]
- 将输出 tensor 放入 BFS 队列


3.2 第二步：BFS 广度优先遍历

主循环逻辑：
  只要队列不为空：
    a) 取出队首的 tensor
    b) 判断该 tensor 是否是 Group 的输入
       - 如果是 → 停止，不继续反向。该 tensor 的数据来自 DDR，不需要向上推
       - 如果不是 → 继续反向推断
    c) 找到生产该 tensor 的 OP，对其每个输入 operand 执行反向推断
    d) 判断每个输入是否需要入队继续传播


3.3 第三步：反向推断的具体规则

每种 OP 都有自己的反向推断逻辑，核心是：已知输出的切分片范围，反推输入需要多大范围。

3.3.1 逐元素操作（Active、Add、Mul 等）
  输入和输出的切分一一对应，输出要 [20,60)，输入也只要 [20,60)。

3.3.2 卷积/池化操作（Conv2D、Pool2D 等）
  由于卷积核的存在，输出的一小片区域依赖于输入的更大范围。
  - 输出要 H 的 [20,60)，kernel_size=3, stride=1, pad=1
  - 输入需要 H 的 [19,61)，比输出向外多出 1 行
  - 这个多出的部分就是 "重叠区域"（overlap/margin），属于冗余计算
  - 不同 OP 的 kernel、stride、dilation、pad 不同，反推出来的 margin 也不同

3.3.3 广播操作
  如果输入的某个维度值为 1（如 N=1、C=1），则不管输出怎么切，输入该维度
  始终是整个 [0,1)，不做切分。

3.3.4 矩阵乘法（MatMul）
  右矩阵的 C 维不切分，常驻 LMEM（标记 hold_in_lmem=true）。

3.3.5 其他特殊操作
  - Reshape：保持数据量不变，映射到不同形状
  - Concat：多个输入拼接到一个输出，反向时需要根据拼接轴反推各输入
  - Slice：输出是输入的子集，反向时扩大范围
  - Softmax/LayerNorm：通常只在最后一维上做，可沿其他维切分
  - Upsample：输出比输入大，反向时缩小


3.4 第四步：是否继续向上传播（入队判断）

一个 tensor 被反推出来后，需要判断是否将其加入 BFS 队列继续向上传播。

判断规则：
  遍历该 tensor 在 Group 内部的所有使用者（consumer OP）：
    - 如果存在某个 consumer OP 还没被处理过 → 暂时不入队，等那个 OP 先被处理
    - 如果所有 consumer OP 都已处理完毕 → 入队，继续向上传播

这个规则的核心目的是保证"逆向拓扑顺序"：
  当从一个 tensor 向上推断其生产者时，必须确保它的所有下游消费者都已经
  被处理过。只有这样才能正确判断该 tensor 的完整切分需求（因为不同消费者
  可能对它有不同要求，详见下一步）。


3.5 第五步（关键）：多分支冲突处理

同一个 tensor 可能被多个不同的下游 OP 引用（多分支结构），例如：

            [Conv1]
           /       \
      [Pool2D]   [Active]
           \       /
           [AddOp]

AddOp 的输出反向推断 Conv1 的输出时：
  - 经过 Pool2D 路径：反推出的 H 范围可能是 [18, 62)（因为 Pool 有 kernel）
  - 经过 Active 路径：反推出的 H 范围可能是 [20, 60)（逐元素，无 margin）
  - 两个结果不一致！

处理策略：

  a) 如果两条路径结果在 H/W 方向上有重叠区域
     → 取并集（最左边界到最右边界），得到一个更大的范围
     → 该 tensor 被标记为 "带 HW margin"（with_hw_margins = true）
     → 下游的 LutOp、CastOp 等需要将 margin 传递给它们自己的使用者
     → 可行，继续

  b) 如果两条路径结果完全无重叠
     → 该 shape_secs 切分方案在这个分支结构下无法成立
     → 该 Group 方案无效，返回失败

  c) 如果重叠区域太大（大于该维度总长的一半，即 > H/2）
     → 冗余计算太多，得不偿失
     → 该 Group 方案无效，返回失败

  d) 特殊情况：
     - CV18xx 芯片不支持 HW margin → 直接失败
     - TPU_DYNAMIC 模式不支持 → 直接失败
     - 某些 OP（如 Conv 的 depthwise 模式）不支持 HW margin → 直接失败
     - F8 量化模式不支持 → 直接失败


3.6 第六步：结束条件

BFS 队列为空时，反向推断完成。

此时 tensor_infos 中包含了 Group 内部所有 tensor（从输出到输入之间的
每条数据边上）的完整切分信息，这些信息将用于后续的：
  - 时间步（timestep）分配：每个 tile 的 Load / Compute / Store 安排在哪个时间步
  - LMEM 地址分配：每个 tile 在片内内存中的起始地址和大小
  - 性能评估（CycleCalculator）：根据切分信息计算执行周期数


四、举例说明
--------------------------------------------------------------------------------

假设 Group 包含三个 OP：{Conv1 → Pool → Conv2}，shape_secs 为 H 切 2 份。

初始化：
  输出 = Conv2 的输出，H=100
  tensor_infos[Conv2.output] = {h: [(0,50), (50,50)]}
  队列 = [Conv2.output]

迭代 1（取 Conv2.output）：
  Conv2 的输入 = Pool 的输出
  Conv2 是卷积，kernel=3, stride=1, pad=1
  输出 H 要 [0,50) → BackwardH 反推 → 输入 H 要 [0,52)
  输出 H 要 [50,100) → BackwardH 反推 → 输入 H 要 [49,100)
  tensor_infos[Pool.output] = {h: [(0,52), (49,52)]}
  注意：两个 tile 在 H 方向重叠了 3 行 (49~52)，这是卷积的 receptive field 导致的
  队列 = [Pool.output]

迭代 2（取 Pool.output）：
  Pool 的输入 = Conv1 的输出
  Pool 也是池化操作，kernel=2, stride=2
  输出 H 要 [0,52) → BackwardH 反推 → 输入 H 要 [0,54) (向外各扩1)
  输出 H 要 [49,52) → BackwardH 反推 → 输入 H 要 [47,54)
  tensor_infos[Conv1.output] = {h: [(0,54), (47,54)]}
  队列 = [Conv1.output]

迭代 3（取 Conv1.output）：
  Conv1 的输入 = Group 的输入（来自 DDR）
  输出 H 要 [0,54) → BackwardH 反推 → 输入 H 要 [0,56)
  输出 H 要 [47,54) → BackwardH 反推 → 输入 H 要 [45,56)
  tensor_infos[Group.input] = {h: [(0,56), (45,56)]}
  Group 的输入 → 不继续入队
  队列 = [] → 结束

最终结果：
  Conv2.output:  [(0,50),  (50,50)]   ← 无重叠（Group 输出）
  Pool.output:   [(0,52),  (49,52)]   ← 重叠 3 行（Conv2 的 kernel 导致）
  Conv1.output:  [(0,54),  (47,54)]   ← 重叠 7 行，重叠加剧（累积效应）
  Group.input:   [(0,56),  (45,56)]   ← 重叠 11 行（两个 OP 的 margin 叠加）

可以看到：随着反向推断的层数增加，每个 tile 需要的输入范围会越来越宽，
重叠部分也越来越大。这就是为什么 Group 不能无限大——太深的 Group 会导致
严重的冗余计算。


五、关键约束条件总结
--------------------------------------------------------------------------------

1. 逐层膨胀：每经过一个 Conv/Pool 类 OP，H/W 范围向外膨胀（margin）
2. 累积效应：多层连续卷积会导致 margin 层层叠加，冗余计算越来越大
3. 多分支一致性：同一 tensor 的多条推断路径结果必须可合并
4. 重叠上限：H 维度重叠超过 H/2 时方案无效（防止冗余计算过大）
5. 终止边界：到达 Group 输入时停止反向（该数据从 DDR 加载）
6. 硬件约束：不同芯片对 HW margin 的支持程度不同
