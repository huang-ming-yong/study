第一部分：核心概念
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

┌─────────────────────────────────────────────────────────────┐
│ 1. 为什么必须逐 block 编译？                                 │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ResNet18:  整个模型 45MB → model_transform + deploy 一把梭  │
│  Llama2-7B: 整个模型 14GB  → 内存放不下，必须拆！            │
│                                                             │
│  做法：把 32 个 transformer block 分别导出、分别编译、        │
│        最后合并成一个 bmodel                                 │
│                                                             │
│  llm_convert.py 做的事：                                     │
│    block_0  → block_0.mlir  → block_0.bmodel  ┐             │
│    block_1  → block_1.mlir  → block_1.bmodel  ├─→ merge     │
│    ...                                         │             │
│    block_31 → block_31.mlir → block_31.bmodel ┘             │
│    embedding  → embedding.bmodel                             │
│    lm_head    → lm_head.bmodel                              │
│                                                             │
│  而且每个 block 有两个版本：                                  │
│    block_N.mlir        → Prefill 阶段用（全尺寸 Attention）   │
│    block_cache_N.mlir  → Decode 阶段用（带 KV Cache 输入）   │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 2. 为什么 7B 必须权重量化？                                   │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Llama2-7B:                                                 │
│    FP16 权重: 7B × 2 bytes = 14 GB                          │
│    BM1684X 总内存: 16 GB                                    │
│                                                             │
│  除了权重还要放：                                             │
│   KV cache:   ~2-4 GB（序列越长越大）                        │
│    中间激活:   ~1-2 GB（推理时的临时数据）                    │
│    运行开销:   ~1 GB                                         │
│                                                             │
│  FP16 → 14 + 4 + 2 + 1 = 21 GB > 16 GB  ❌ 放不下!          │
│  W8   →  7 + 4 + 2 + 1 = 14 GB ≤ 16 GB  ✅                 │
│  W4   → 3.5 + 4 + 2 + 1 = 10.5 GB     ✅ 最宽裕            │
│                                                             │
│  W4/W8 是"仅权重量化"（Weight-Only）：                        │
│    W8A16 = 8-bit 权重 + FP16 激活（精度最高）                 │
│    W4A16 = 4-bit 权重 + FP16 激活（最省内存）                 │
│    激活值不量化，保持 FP16                                    │
│                                                             │
│  权重量化算法: RTN (Round To Nearest)                         │
│    per-channel（W8）或 per-group（W4, group_size=64）         │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 3. Prefill 与 Decode 两个阶段                                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  例子：输入 "今天天气很不错"（8 个 token）                     │
│                                                             │
│  ┌─────────── Prefill ──────────┬────── Decode ──────┐      │
│  │                              │                    │      │
│  │  一次处理 8 个 token          │  一次出 1 个 token  │      │
│  │  计算矩阵乘法，算力密集型      │  查 KV Cache，带宽密集│     │
│  │  输出第一个 token: "，"       │  输出: "适合"      │      │
│  │  把 KV 存入 Cache             │       "户外"      │      │
│  │                              │       "运动"      │      │
│  │                              │       "。"        │      │
│  └──────────────────────────────┴────────────────────┘      │
│                                                             │
│  编译时要同时生成两个版本：                                    │
│    block.mlir        → Prefill（输入全部 prompt token）       │
│    block_cache.mlir  → Decode（额外输入: 历史的 KV Cache）    │
│                                                             │
│  关键词：KV Cache = 注意力机制中已计算的 Key/Value 矩阵         │
│          避免了每次 decode 重新计算整个序列                    │
└─────────────────────────────────────────────────────────────┘

【环境准备】

  1. 下载模型
     git lfs install
     git clone https://huggingface.co/meta-llama/Llama-2-7b-hf

  2. 进入 Docker
     docker start tpu-mlir
     docker exec -it tpu-mlir bash
     source /workspace/tpu-mlir/envsetup.sh

  3. 预览配置（建议先跑，确认参数正确）
     cd /workspace
     llm_convert.py \
       -m Llama-2-7b-hf \
       -s 2048 \
       -q w4bf16 \
       -g 64 \
       -c bm1684x \
       -o llama2_7b_W4BF16 \
       --dry_run


【步骤一】编译 bmodel（一键完成逐 block 编译 + 合并）

  # W4BF16 版本（4-bit 权重，推荐）
  llm_convert.py \
    -m Llama-2-7b-hf \
    -s 2048 \
    -q w4bf16 \
    -g 64 \
    -c bm1684x \
    -o llama2_7b_W4BF16

  # W8BF16 版本（8-bit 权重，精度更高）
  llm_convert.py \
    -m Llama-2-7b-hf \
    -s 2048 \
    -q w8bf16 \
    -c bm1684x \
    -o llama2_7b_W8BF16

  参数说明：
    -m   模型目录（HuggingFace 格式）
    -s   最大序列长度（越长越费 KV Cache）
    -q   bf16 | f16 | w8bf16 | w4bf16 | w8f16 | w4f16
    -g   量化组大小（W4 默认 64）
    -c   目标芯片
    -o   输出目录

  编译时间：约 1-2 小时（取决于机器性能）


【步骤二】在 BM1684X 芯片上运行文本生成

  1. 把 bmodel 拷到芯片服务器
     scp llama2_7b_W4BF16/*.bmodel user@芯片IP:~/llm/

  2. 在芯片服务器上克隆 LLM-TPU 运行时
     git clone https://github.com/sophgo/LLM-TPU.git
     cd LLM-TPU/models/Llama2/python_demo
     pip3 install -r requirements.txt

  3. 运行
     python3 run.py \
       --model ~/llm/llama2_7b_W4BF16_xxx.bmodel \
       --tokenizer /path/to/Llama-2-7b-hf \
       --prompt "Hello, how are you?"

【对比 resnet18 和 llama2 的编译命令】

  ┌──────────────┬──────────────────────────────────────────┐
  │              │              编译命令差异                  │
  ├──────────────┼──────────────────────────────────────────┤
  │ ResNet       │ model_transform → model_deploy            │
  │ (整个模型)   │ --quantize F16 / INT8                     │
  │              │ 一条 deploy 搞定                          │
  ├──────────────┼──────────────────────────────────────────┤
  │ Llama2       │ model_transform → model_deploy

  新增关键参数：
    --q_group_size 64    量化组大小（W4 的 per-group 粒度）
    --addr_mode io_alone 地址模式（LLM 专用，输入输出独立地址空间）
    --quant_input        输入的量化（让数据流前后对齐）
    --quant_output       输出的量化
