============================================================
第七周概念：用你已经会的东西来解释
============================================================

你之前跑过这些命令：
  model_transform  →  把 ONNX 转成 .mlir
  run_calibration  →  统计激活范围，生成校准表
  model_deploy     →  把 .mlir 编译成 .bmodel

第七周就是要搞清楚：这些命令背后到底干了什么。

------------------------------------------------------------
一、别慌，你要看的其实就一条流水线
------------------------------------------------------------

把 tpu-mlir 想象成一个工厂：

  原材料（ONNX模型）
       │
       ▼
  [车间1: 前端]    把 ONNX 翻译成 tpu-mlir 自己能懂的"中间语言"
       │            这就是你跑 model_transform 背后干的事
       ▼
  [车间2: Top层]   对中间语言做各种"优化手术"（比如把 Conv+BN 合并）
       │            改的是 include/ 里定义的算子，改逻辑在 lib/ 里
       ▼
  [车间3: Lowering] 把通用的算子描述，翻译成 BM1684X 专用指令
       │            关键转换在这里发生
       ▼
  [车间4: LayerGroup] 决定哪些算子打包一起算、怎么在有限的片上内存里搬数据
       │            这是决定性能的地方
       ▼
  [车间5: Codegen]  生成最终的二进制 .bmodel 文件
       │
       ▼
  成品（bmodel）

第七周就是：挑一个算子（Conv），跟着它走完这5个车间，搞清楚每个车间对它做了什么。

------------------------------------------------------------
二、用大白话解释那些术语
------------------------------------------------------------

IR (Intermediate Representation)
  = 中间表示，就是"车间之间传递的半成品"
  = 你跑 model_transform 出来的 .mlir 文件就是 IR
  = 打开看看就明白了：里面是一行一行的 text，描述每个算子的输入/输出/参数
  → 练：随便找一个你之前跑出来的 .mlir 文件，用 less 打开看一眼长什么样

SSA (Static Single Assignment)
  = 每个变量只被赋值一次
  = 你看到的 .mlir 文件里，每个 %数字 只出现一次在等号左边
  → 不用深究，知道名字就行

Basic Block
  = 一段顺序执行的代码块，没有分叉
  = 在 .mlir 里不明显，看 Toy Tutorial 的图更好理解

Operation (Op)
  = 一个算子，比如 Conv、Add、MatMul
  = 在 .mlir 文件里每一行就是一个 Op

TableGen (.td 文件)
  = MLIR 的"配置文件语言"，用来声明"我有一个叫 Conv 的算子，它有这些输入、这些输出、这些属性"
  = 不用学 TableGen 语法，就学会一件事：看到 .td 文件能认出"哦，这是在定义算子"
  → 打开 include/tpu_mlir/Dialect/Top/IR/TopOps.td，搜 "def Top_ConvOp"，感受一下

Pass
  = 一次"对 IR 做修改"的操作
  = 比如"把所有 Conv+BN 相邻的模式合并成一个新算子"就是一个 Pass
  = 编译器 = 一串 Pass 按顺序执行

PassManager
  = Pass 的调度器，决定谁先谁后

Pattern Rewrite
  = 一个 Pass 的具体实现方式：定义"匹配什么 IR 模式，替换成什么 IR 模式"

------------------------------------------------------------
三、你真正要看的就一个文件链
------------------------------------------------------------

别被理论吓到。第七周的核心任务就一件事：

  选 Conv 算子，从源头追到尾，搞清楚它经历了什么。

具体就是按这个顺序打开文件，每个文件只问三个问题：

  1. 这个文件在哪个"车间"？
  2. Conv 在这个车间里被做了什么操作？
  3. 操作后的结果和操作前有什么不同？

文件链（按顺序看）：

  车间1: python/tools/model_transform.py
          → 这是你敲命令的入口，看看 main 函数怎么调用后面的流程
          → 搜 "model_transform"，找到主逻辑在哪

  车间2: python/transform/OnnxConverter.py
          → ONNX 的 Conv 算子被转成 Top Dialect 的 top.Conv
          → 搜 "Conv" 找转换函数

  车间3: lib/Conversion/TopToTpu/BM1684X/Conv.cpp
          → 这里是核心：通用的 Conv 怎么变成 BM1684X 专用的 Conv
          → 找 loweringConv 或类似的函数名
          → 对比 F16 版本和 INT8 版本做的事有什么不同

  车间4: lib/Dialect/Tpu/Transforms/LayerGroup/GroupMethod.cpp
          → Conv 和其他算子怎么被分到同一组
          → 不需要全看懂，就看"分组的规则是什么"

  车间5: lib/Dialect/Tpu/Transforms/Codegen/BM168xCodegen.cpp
          → IR 怎么变成二进制指令
          → 知道有这个东西就行

关键技巧：
  - 看不懂的函数不要硬啃，先跳过，回头再看
  - 每个文件只记一句话（用中文写）：这个文件对 Conv 做了什么
  - 遇到不认识的类型/类名，grep 搜一下在哪定义的，不要求全看懂
  - 实在看不懂的 C++ 语法，先标出来，组会问

------------------------------------------------------------
四、第一件事：打开一个 .mlir 文件看看 IR 长什么样
------------------------------------------------------------

如果连 IR 什么样都没见过，前面全是空话。

找一个你之前用 model_transform 生成的 .mlir 文件，用编辑器打开。
你会看到类似这样的内容（不一定是真的，但形式差不多）：

  %0 = top.Conv(%input, %weight) {kernel_shape = [3,3], stride = [1,1]}
  %1 = top.Relu(%0)
  %2 = top.MaxPool(%1) {kernel_shape = [2,2], stride = [2,2]}

这就是 IR —— 每一行是一个算子，%数字 是数据在算子间流动的名字。
整个 tpu-mlir 编译器就是把这些东西一步步变换，最后变成板子能跑的二进制。

如果你之前没保存 .mlir 文件，现在跑一条命令生成一个看看：
  cd tpu-mlir && source /workspace/tpu-mlir/envsetup.sh
  然后随便跑一个 model_transform 生成一个 .mlir 文件用 cat/less 看
