========================================================================
C++ 模板（template）—— 零基础补充
========================================================================

【问题】为什么 OpRewriterPatternEx<ConvOp> 要塞一个 ConvOp 在尖括号里？


========================================================================
一、没有模板的世界：为每个算子写一个父类
========================================================================

假设 MLIR 没有模板这个特性。你要给 Conv、Add、MatMul 三个算子写 pattern 基类：

  // 给 Conv 用的
  class PatternForConv {
    ConvOp op;                // 死绑 ConvOp
    void matchAndRewrite(ConvOp op) { ... }
  };

  // 给 Add 用的（代码跟上面几乎一样，只是 ConvOp → AddOp）
  class PatternForAdd {
    AddOp op;                 // 死绑 AddOp
    void matchAndRewrite(AddOp op) { ... }
  };

  // 给 MatMul 用的（又写一遍...）
  class PatternForMatMul {
    MatMulOp op;              // 死绑 MatMulOp
    void matchAndRewrite(MatMulOp op) { ... }
  };

100 个算子就要写 100 个几乎一模一样的类，只因为其中一个类型名不同。
这就是"代码重复"，程序员最恨的事情。


========================================================================
二、模板解决什么：把"变的地方"变成参数
========================================================================

把上面三个类并排看，除了类型名不同，其余一模一样：

  class PatternForConv   {  ConvOp   op; ... };
  class PatternForAdd    {  AddOp    op; ... };
  class PatternForMatMul {  MatMulOp op; ... };
                          └──┬──┘
                      只有这里不一样！

模板就是把"不一样的地方"变成一个参数，让用户自己填：

  template <typename SourceOp>        // SourceOp 就是一个"待填的坑"
  class OpRewriterPatternEx {
    SourceOp op;                      // 所有地方用 SourceOp 占位
    void matchAndRewrite(SourceOp op) { ... }
  };

使用时：
  OpRewriterPatternEx<ConvOp>    →  所有 SourceOp 替换为 ConvOp
  OpRewriterPatternEx<AddOp>     →  所有 SourceOp 替换为 AddOp
  OpRewriterPatternEx<MatMulOp>  →  所有 SourceOp 替换为 MatMulOp

一个类搞定所有算子。模板 = 填空题。


========================================================================
三、用你生活中的例子来理解
========================================================================

你给全班同学写通知，内容都一样，只差名字：

  "___同学，请于明天上午9点到办公室。"

你不用给 40 个人手写 40 封，而是在 Word 里贴一个"合并域"，
填不同的名字，打印 40 份。

  模板（通知正文）： "___同学，请于明天上午9点到办公室。"
  参数（具体名字）： <张三> <李四> <王五> ...

这里：
  通知正文  =  OpRewriterPatternEx（模板类）
  合并域    =  SourceOp（typename 声明的占位符）
  张三/李四 =  ConvOp / AddOp / MatMulOp（你填进去的具体类型）


========================================================================
四、用代码演示：手工展开
========================================================================

这是 OpRewriterPatternEx.h 里的真实模板（简化版）：

  template <typename SourceOp>                              // 声明：SourceOp 是占位符
  class OpRewriterPatternEx : public mlir::OpRewritePattern<SourceOp> {
  public:
    OpRewriterPatternEx(mlir::MLIRContext *context, ...) { ... }

    mlir::LogicalResult
    matchAndRewrite(SourceOp op,                            // ← SourceOp 出现在这里
                    mlir::PatternRewriter &rewriter) const override {
      ...
      mlir::LogicalResult result = matchAndRewriteImpl(op, rewriter);
      ...
    }

  protected:
    virtual mlir::LogicalResult
    matchAndRewriteImpl(SourceOp op,                        // ← 这里也有
                        mlir::PatternRewriter &rewriter) const = 0;
  };

当你写 OpRewriterPatternEx<ConvOp> 时，编译器做的事情等价于：

  1. 把模板里的 SourceOp 全部替换成 ConvOp
  2. 生成一份"只有 ConvOp 的版本"

替换后的效果（编译器实际生成的代码）：

  class OpRewriterPatternEx_ConvOp版本 {             // 实际类名是编译器内部用的
    matchAndRewrite(ConvOp op, PatternRewriter &rewriter) { ... }
    virtual matchAndRewriteImpl(ConvOp op, ...) = 0;
  };

如果你还写了 OpRewriterPatternEx<AddOp>，编译器会再生成一份 AddOp 的版本。
两份互不干扰。


========================================================================
五、源码里的证据
========================================================================

你打开 Conv.cpp，全文件搜索 "ConvOp"：

  struct Conv1dTo2d : public OpRewriterPatternEx<ConvOp>     {...};  → 处理 Conv
  struct Conv3dTo2d : public OpRewriterPatternEx<ConvOp>     {...};  → 处理 Conv
  struct Conv1x1Convkxk2dMerge : public OpRewriterPatternEx<ConvOp> {...};  → 处理 Conv

所有规则都填了 <ConvOp>，因为 Conv.cpp 就是专门处理 Conv 算子的。

如果有个 Add.cpp（处理 Add 算子的），里面会是：

  struct AddMulMerge : public OpRewriterPatternEx<AddOp> { ... };

用的是同一个 OpRewriterPatternEx 模板，但填进去的参数不同。


========================================================================
六、模板的完整语法
========================================================================

  template <typename 占位符名>
  class/struct/函数 的定义

  template   →  关键字。"下面我要声明一个模板"
  <typename 占位符名>  →  声明占位符。"typename" = 这个占位符将来会被替换成一个类型名。
                          占位符名可以随便取：
                            typename T          → T 最常用
                            typename SourceOp   → SourceOp，更有语义
                            typename Whatever   → 也行，但别人看不懂
  后面跟类/结构体/函数的定义。

使用时要填参数：
  类名<具体类型>    →  OpRewriterPatternEx<ConvOp>
                     →  std::vector<int64_t>    ← 这也是模板！vector 是一个模板类
                     →  std::shared_ptr<T>      ← 也是模板


========================================================================
七、多参数的模板
========================================================================

一个模板可以有多个参数，比如：

  template <typename T, int N>
  class Array {
    T data[N];            // T = 元素类型, N = 数组大小
  };

  Array<float, 100>   → float data[100];
  Array<int, 3>       → int data[3];

尖括号里可以有：
  - 类型参数（typename / class） → ConvOp, float, int64_t
  - 非类型参数（具体的值）       → 100, 3, true


========================================================================
八、总结
========================================================================

  OpRewriterPatternEx<ConvOp>

  OpRewriterPatternEx  →  一个模板类（通用配方，适用于任何算子）
  <ConvOp>             →  你填的参数（指定"这次我要处理 Conv 算子"）
  合起来               →  "专门处理 Conv 算子的 Pattern 基类"

  本质：模板让你写一份代码，适用于无数种类型。尖括号就是填参数的地方。
