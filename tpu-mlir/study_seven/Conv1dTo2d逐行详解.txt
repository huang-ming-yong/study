Conv1dTo2d 逐行详解 —— C++ 语法 + 代码作用
========================================================================

【先备知识：几个反复出现的 C++ 语法】

  1. 箭头 -> 和点 . 的区别：
     - op.getKernelShape()    →  op 是一个"实体对象"，用 . 调用它的函数
     - kernel->size()         →  kernel 是一个"指针（地址）"，用 -> 调用它指向的对象的函数
     记住：指针用 ->，实体用 .。指针就是"门牌号"，你得先顺着门牌号找到房子，才能进去。

  2. auto：
     - auto kernel = xxx;     →  让编译器自动推断 kernel 的类型，你不用手写类型名
     - 比如 xxx 返回的类型是 std::shared_ptr<std::vector<int64_t>>，
       你写 auto，编译器自动帮你填。省得你记一长串类型名。

  3. std::vector<int64_t>：
     - 就是一个"可以变长的数组"
     - {3, 1} 表示一个数组，第 0 个元素 = 3，第 1 个元素 = 1
     - push_back(1) 在数组末尾追加一个元素 1
     - 原来的数组是 [3]，执行 push_back(1) 后变成 [3, 1]

  4. *指针 的含义（解引用）：
     - kernel 是一个指针（门牌号）
     - *kernel 才是指针指向的那个真实数据
     - 比如 module::getI64Array(...) 返回的是"指向数组的指针"，
       你加一个 * 才能拿到那个数组本身

  5. 命名空间 和 ::：
     - mlir::MLIRContext     →  mlir 命名空间里的 MLIRContext 类
     - module::getI64Array   →  module 命名空间里的 getI64Array 函数
     - 可以理解为"姓.名"，避免同名冲突。就像"张伟"和"李伟"是两个不同的人。

  LogicalResult matchAndRewriteImpl(ConvOp op,

  拆开看：
    LogicalResult    →  返回值类型。这是一个"逻辑结果"，只有两种值：success() 或 failure()
    matchAndRewriteImpl →  函数名。"匹配并改写"（match = 匹配，rewrite = 改写，impl = 实现）
    ConvOp op        →  参数。ConvOp 是 Conv 算子在 C++ 里的类型，op 是参数名，
                         代表 "当前被扫描到的那个 Conv 算子"

  白话：
    这个函数是规则的核心。MLIR 框架每扫描到一个 Conv 算子，就把这个算子作为
    参数 op 传进来，然后调用这个函数。你的任务就是：
      - 检查这个 op 是不是你要处理的那种（match）
      - 如果是，就改它（rewrite）
      - 返回 success() 表示"我改了"；返回 failure() 表示"不是我处理的那种，跳过"

  注意：这个函数名叫 matchAndRewriteImpl 而不是 matchAndRewrite，
        因为 OpRewriterPatternEx 是 tpu-mlir 自己包装的类，
        底层最终会调用标准的 matchAndRewrite。

                                    PatternRewriter &rewriter) const override {

  拆开看：
    PatternRewriter  →  参数类型。"IR 改写器"，一个用来修改 IR 的工具类
    &                →  引用符号。表示 rewriter 是"别名"，不是复制一份新对象
                        好处：不需要拷贝整个对象，快；而且对 rewriter 的修改会影响原始对象
    rewriter         →  参数名
    const            →  这个函数"不会修改 Conv1dTo2d 对象本身的任何成员变量"
    override         →  "重写父类的函数"。表示父类也有一个 matchAndRewriteImpl，
                        我这里用自己的实现覆盖它

  白话：
    rewriter 就是你的"工具箱"：
      - 你想改某个算子的属性？用 rewriter
      - 你想在 IR 里插入一个新算子？用 rewriter
      - 你想删掉某个算子？用 rewriter

    这个参数是引用（&）传递的，不是复制。你可以把它理解为：
    "给你一把改 IR 的钥匙，你直接用，不用复制一把新的。"

    const = 保证我不会乱动自己类的成员变量。
    override = 告诉编译器"我是真的要覆盖父类函数，不是碰巧同名"。
               如果你写错了函数名（比如少了一个字母），编译器会报错提醒你。

  拆开看：

      - kernel 是 [3]     → size = 1，不等于 1？假，不进入 {}，继续往下执行
      - kernel 是 [3, 3]  → size = 2，不等于 1？真，进入 {}，return failure() 退出

    这是"守卫条件"（Guard Clause）模式：
      先检查你是不是我的目标场景，不是就立刻退出。
      所有优化规则都这样写——在最前面把所有"不匹配"的情况排除掉。

    vfilterShape.push_back(1);

  拆开看：
    vfilterShape      →  上一行得到的形状数组
    .push_back(1)     →  在数组末尾追加一个元素 1

  白话：
    vfilterShape 原来是 {64, 3, 3}，push_back(1) 后变成 {64, 3, 3, 1}。
    多出来的一维大小是 1，相当于"伪造成 4 维张量"，但实际数据量不变。

    为什么这样做？
      BM1684X 芯片只认识 4 维张量的 2D 卷积（N, C, H, W）。
      1D 卷积的权重是 3 维的（O, I, K），补一维变成 4 维（O, I, K, 1），
      芯片就能处理了。多出来的那维大小是 1，不影响计算结果。

========================================================================
总览：整段代码做了什么
========================================================================

  输入 IR：
    %3 = "top.Conv"(%in, %w, %b) {
      kernel_shape = [3],
      strides = [2],
      pads = [1, 1],
      dilations = [1]
    } : (tensor<1x3x100xf32>, tensor<64x3x3xf32>, tensor<64xf32>)
        -> tensor<1x64x98xf32>

  输出 IR：
    %3 = "top.Conv"(%in, %w, %b) {
      kernel_shape = [3, 1],       ← 多了一维
      strides = [2, 1],            ← 多了一维
      pads = [1, 0, 1, 0],         ← 从 2 个数变成 4 个数（插入了 0）
      dilations = [1, 1]           ← 多了一维
    } : (tensor<1x3x100x1xf32>, tensor<64x3x3x1xf32>, tensor<64xf32>)
        -> tensor<1x64x98x1xf32>   ← 所有形状都补了 1

  所有数值都没变，只是描述方式从"1 维"变成了"2 维"（其中一个维度大小为 1）。


========================================================================
函数调用流程（框架怎么调用这个规则）
========================================================================

  Canonicalization 框架：
    1. 扫描 IR，碰到一个 Conv 算子
    2. 遍历所有注册的规则（Conv1dTo2d 是其中之一）
    3. 创建一个 PatternRewriter（工具箱）
    4. 调用 matchAndRewriteImpl(op, rewriter)
    5. 如果返回 success() → 标记"IR 已修改"，重新从头扫描
    6. 如果返回 failure() → 跳过，试下一条规则
    7. 直到 IR 不再变化

  注意：每次成功修改后，框架会重新从头扫描！
        这意味着如果你连续改了两次，第一条规则可能被第二次触发，
        也可能因为条件不满足而不触发（因为 IR 已经变了）。


========================================================================
四种属性的修改对比

  属性         1D 值      2D 值      说明
  ─────────────────────────────────────────
  kernel_shape [3]        [3, 1]      kernel 大小从 1 个数变成 2 个数
  strides      [2]        [2, 1]      步长新增的维度设为 1（不跳）
  pads         [1, 1]    [1, 0, 1, 0] 上下补 0，左右保留原值
  dilations    [1]        [1, 1]      膨胀率新增维度设为 1（不膨胀）

  共同规律：新增的维度参数全部设成"不影响计算"的值。
           kernel=1, stride=1, pad=0, dilation=1 → 在这一维上没有实质性操作。
